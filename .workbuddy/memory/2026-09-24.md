## 创作应用图标（提交 1629795）

用户要求「帮我创作一张图标，最好考虑下应用主题色」。流程：读 CSS 变量定色 → 出 3 个
候选 → 精修定稿 → 生成 icns → 打包验证。

### 定色（不另起一套色）

从 `static/css/style.css` 的 `:root` 取：`--primary: #6366f1`、
`--primary-gradient: #6366f1 → #a855f7 → #ec4899`。底板渐变直接照搬品牌三色
（微调为 `#6366F1 → #8B5CF6 → #A855F7 → #D946EF`），保证 Dock 图标与界面同源同调。

### 设计取舍

三个候选：U 形收纳槽+箭头 / 经典托盘+箭头 / 圆环+穿透箭头。
- 方案 1 **失败**：箭头 V 的两端与 U 的竖线顶端在视觉上撞在一起，成了混乱的三叉形。
- 方案 3 **拥挤**：圆环外缘贴近底板边缘，箭头与圆环比例失衡。
- 方案 2 **胜出**：识别度最高、视觉重量最均衡。定稿为「下落箭头 + 承接托盘」，
  纯白、笔画 62、圆头端点圆角拐点，另加极轻的符号投影让符号从底板上浮起。

### 产物

- `assets/icon.svg`（唯一真源，1024 画布，语义化 id，无冗余节点）
- `assets/icon.png` / `icon.icns`（由 SVG 生成，包内 md5 与源一致）
- `assets/README.md`（色值表、画布规范、重生成步骤）
- `scripts/render_svg.py`（新增）、`scripts/build_app_icon.py`（增强：支持 `--svg`）

### 两个真实发现

1. **SVG 注释里的双连字符**：初版注释写了 CSS 变量名 `--primary-gradient`，而 XML
   规范禁止注释内出现 `--`。表现是 qlmanage 渲染出一张「XML 解析错误」的占位图，
   而 **Chrome 完全不报错**（按 HTML 规则解析内联 SVG）。危险点在于应用自身的
   WKWebView 也是 WebKit，同一份文件在 Safari / WKWebView 里会直接拒渲染。
   已在 `render_svg.py` 加 XML 预校验（`xml.etree.ElementTree.parse`）。
2. **Chrome headless 在用户开着 Chrome 时挂住**：无论是否指定 `--user-data-dir`
   都超时（60s+，`/tmp` 与 `~/Library/Caches` 均失败）。改用 `qlmanage`
   （系统 QuickLook）后稳定，且输出本身就带 alpha 通道。
   → 渲染后端首选 qlmanage，Chrome 仅作兜底。

### 环境备忘

- `iconutil -c iconset -o <path>` 的输出路径**必须**以 `.iconset` 结尾。
- 判断 PNG 是否带透明：读 IHDR 的 color_type，**6 = RGBA**，2 = RGB 无 alpha。
- sips + iconutil 生成 icns **不需要任何第三方库**（Pillow 只有生成 .ico 时才需要）。
- 渲染脚本已固化：`scripts/render_svg.py`（可被 import，`render(svg, out, size)`）。

## 追加：P2 交付项现状核实（图标✅ / 版本号✅ / Universal❌ / 签名公证❌）

用户问「P2 这些都做了吗，签名用的什么方式」。实测核实，不凭记忆：

| 项 | 状态 | 证据 |
|---|---|---|
| 图标 | ✅ | `CFBundleIconFile=icon.icns`，包内 md5 与源一致 |
| 版本号 | ✅ | `CFBundleShortVersionString=2.4.0.0` |
| Universal 架构 | ❌ | `file` → Mach-O **arm64**；`lipo -archs` → 仅 arm64 |
| 签名 + 公证 | ❌ | `Signature=adhoc` / `TeamIdentifier=not set` / `spctl` → **rejected** / 无公证票据 |

### 签名机制（实测结论）

PyInstaller 在 macOS 的默认行为：spec 里 `codesign_identity=None` → 对 .app 及内部
**所有 Mach-O（含内嵌 ffmpeg）逐个做 adhoc 签名**（`codesign -s -`）。

- `codesign --verify --deep --strict` **通过**（`valid on disk` + `satisfies its
  Designated Requirement`）—— adhoc 是「完整性密封」，能证明文件未被篡改；也顺带
  证明了 `cp -R` 部署没有破坏签名。
- 但它**不是身份证明**：`TeamIdentifier=not set`、无 Developer ID 证书、
  entitlements 为空、无公证票据。`spctl -a -vv -t exec` → **rejected**，
  这就是「别人下载后打不开」的直接证据（Gatekeeper 不认 adhoc 信任链）。
- 本机自己跑没问题：本地/自建产物不带 `com.apple.quarantine` 属性。

### universal2 的技术前提（实测：本机做不了）

- 本地 Python 是 **arm64 thin**（`lipo -archs` → arm64），而 `target_arch='universal2'`
  要求解释器本身与全部 C 扩展都是 universal2。
- 涉及的 C 扩展：`pydantic_core` / `uvloop` / `httptools` / `watchfiles` / `pyobjc` / `yaml`。
- → 要做真 universal2 必须换 universal2 的 Python（python.org 官方安装包）并重装全部依赖；
  或改由 CI 分架构出包。

### 顺带发现的 CI 缺陷（.github/workflows/build-desktop.yml）

1. macOS 资产名 `UniversalDownloader-macOS-Universal.zip` **名不符实** —— runner 是
   arm64，产物只有 arm64，Intel 用户下载后根本打不开。
2. CI 用 **Python 3.10**（第 34 行），而本地构建用 **3.13** —— 版本漂移，同一个 spec
   在两处构建出的不是同一个东西。
3. matrix 里的 `asset_path`（第 19/22/25 行）是**死配置**：第 71 行上传时实际用的是
   `dist/${{ matrix.artifact_name }}`，该字段从未被引用。

### 环境备忘（踩坑）

- **shell 里含 GitHub Actions 表达式（美元符号 + 双层花括号）的文本会被 zsh 当成参数
  展开**，报 `Bad substitution: {`，**整条命令直接不执行** —— 而且 heredoc 用引号定界符

## 追加：开源前敏感信息审计（结论）

用户问「代码里存在敏感信息吗，比如个人信息、账号密码、签名密钥」。对**当前工作区**与
**全部分支的完整 git 历史**（含 dangling 对象）做了扫描。

### 扫描覆盖范围
- 工作区：52 个被跟踪文件 + 未跟踪文件（0 个），逐个正则匹配
- 历史：211 个 blob（覆盖 main / ads / desktop-nas / feature/cloudflare-support 全部分支），
  按对象去重后扫描
- 补充维度：图片/图标元数据与可打印字符串、dangling 对象内容、设备 UUID 路径、
  URL 内嵌凭据、第三方账号标识、提交身份信息

### 干净的部分（重点）
- **无任何私钥、API key、云服务 token、数据库连接串、URL 内嵌凭据**
- **无真实 SESSDATA**：只有 `your_sessdata_here` 这类占位符示例
- 无 `/Users/<用户名>/` 绝对路径、无内网 IP、无设备 UUID 路径
  —— 写记忆时统一用 `~` 与仓库相对路径，这个习惯确实见效了
- 图片资产无元数据泄露（`icon.png` 无 tEXt/iTXt 块）；icns 里的 `NSKeyedArchiver`
  字符串是 icns 格式自身的正常内容，不是敏感信息
- remote 用 SSH（`git@github.com:...`），URL 里没有内嵌凭据
- 7 个 dangling 对象是旧版 `index.html` / `style.css`，无额外敏感内容

### 复现方法

### 经验
- **只扫工作区是不够的**：敏感文件删掉后 blob 仍可被 `git cat-file` 取出，
  必须扫 `git rev-list --all --objects` 的全部对象。
- **`git ls-files` 之外的三个盲点**：dangling 对象（`--batch-all-objects` 才能覆盖）、
  二进制资产的元数据、提交身份信息（`%an <%ae>`）。
- 扫描时**不要把命中的真实值完整打印**到日志/对话里，只显示前后缀 + 长度。
