# 2026-09-24

## 创作应用图标（提交 1629795）

用户要求「帮我创作一张图标，最好考虑下应用主题色」。流程：读 CSS 变量定色 → 出 3 个
候选 → 精修定稿 → 生成 icns → 打包验证。

### 定色（不另起一套色）

从 `static/css/style.css` 的 `:root` 取：`--primary: #6366f1`、
`--primary-gradient: #6366f1 → #a855f7 → #ec4899`。底板渐变直接照搬品牌三色
（微调为 `#6366F1 → #8B5CF6 → #A855F7 → #D946EF`），保证 Dock 图标与界面同源同调。

### 设计取舍

三个候选：U 形收纳槽+箭头 / 经典托盘+箭头 / 圆环+穿透箭头。
- 方案 1 **失败**：箭头 V 的两端与 U 的竖线顶端在视觉上撞在一起，成了混乱的三叉形。
- 方案 3 **拥挤**：圆环外缘贴近底板边缘，箭头与圆环比例失衡。
- 方案 2 **胜出**：识别度最高、视觉重量最均衡。定稿为「下落箭头 + 承接托盘」，
  纯白、笔画 62、圆头端点圆角拐点，另加极轻的符号投影让符号从底板上浮起。

### 产物

- `assets/icon.svg`（唯一真源，1024 画布，语义化 id，无冗余节点）
- `assets/icon.png` / `icon.icns`（由 SVG 生成，包内 md5 与源一致）
- `assets/README.md`（色值表、画布规范、重生成步骤）
- `scripts/render_svg.py`（新增）、`scripts/build_app_icon.py`（增强：支持 `--svg`）

### 两个真实发现

1. **SVG 注释里的双连字符**：初版注释写了 CSS 变量名 `--primary-gradient`，而 XML
   规范禁止注释内出现 `--`。表现是 qlmanage 渲染出一张「XML 解析错误」的占位图，
   而 **Chrome 完全不报错**（按 HTML 规则解析内联 SVG）。危险点在于应用自身的
   WKWebView 也是 WebKit，同一份文件在 Safari / WKWebView 里会直接拒渲染。
   已在 `render_svg.py` 加 XML 预校验（`xml.etree.ElementTree.parse`）。
2. **Chrome headless 在用户开着 Chrome 时挂住**：无论是否指定 `--user-data-dir`
   都超时（60s+，`/tmp` 与 `~/Library/Caches` 均失败）。改用 `qlmanage`
   （系统 QuickLook）后稳定，且输出本身就带 alpha 通道。
   → 渲染后端首选 qlmanage，Chrome 仅作兜底。

### 环境备忘

- `iconutil -c iconset -o <path>` 的输出路径**必须**以 `.iconset` 结尾。
- 判断 PNG 是否带透明：读 IHDR 的 color_type，**6 = RGBA**，2 = RGB 无 alpha。
- sips + iconutil 生成 icns **不需要任何第三方库**（Pillow 只有生成 .ico 时才需要）。
- 渲染脚本已固化：`scripts/render_svg.py`（可被 import，`render(svg, out, size)`）。
